# Contributing to RivexMP

1. Open an issue describing the change and its public API implications.
2. Use small commits and preserve protocol versioning.
3. Include tests for validation, networking and security-sensitive changes.
4. Run `npm test`, `npm run build`, `cargo test --workspace` and `cargo fmt --all`.
5. Follow the license boundaries in `LICENSES.md` and use SPDX headers on new source files.
6. Do not submit proprietary GTA content, leaked information, native game hooks, DRM bypasses or unauthorized anti-cheat bypasses.

Pull requests should document any breaking configuration/API changes and include reproducible test commands.
